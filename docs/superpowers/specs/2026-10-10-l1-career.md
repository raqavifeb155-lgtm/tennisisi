## 2. Данные

```gdscript
SaveData.career = {
  "v": 1, "gen": 1, "id": "p1", "name": "Дима",   # имя героя (см. 6); "" только у старого сейва до загрузки
  "start_played": 37, "season": 2, "in_season": 1, "age": 22,
  "season_pts": 90, "cells": [{"loc": "park", "pts": 90, "round": 2, "champion": false, "final": false}],
  "seasons": [{"season": 1, "pts": 410, "rank": 270, "titles": 0, "gold": 40, "cells": [...]}],
  "runs": 5, "titles": 0, "career_pts": 500, "best_rank": 270,
  "season_due": 0,          # сезон, итоги которого ещё не показаны
  "retire_due": false, "early": false,
  "heirs": [],              # кандидаты, зафиксированные к этой пенсии (перезапуск не перебрасывает)
  "origin": "start" | "free" | <id источника>, "relic": {},   # реликвия, с которой начал
  "retired": [ <запись ушедшего, см. 4> ],
}
```

- `_score` уже считает `lifetime_xp` (пенсия сбрасывает навыки — счёт не падает) + новое слагаемое
  `career.gen × 10` (после пенсии копия строго «больше» облачной копии до неё).
- `Skills.to_profile()` / `Skills.load_profile(p)` — профиль навыков словарём
  `{"xp": {}, "perks": [], "pending": [], "points": 3}`; `Skills.profile_from_levels(levels, points)`.
  Статические `Skills.xp/perks/pending/points` остаются: профиль — снимок и загрузка, не замена.
- Флаг `relic` в данных вещи: `item["relic"] = true`, `item["relic_of"] = "имя"` — одно поле,
  скины потока F читают его по желанию (золотая нить — F). Реликвия кладётся в
  `Locker.next_items()` и приходит в первый забег наследника сама (как купленная вещь).

## 3. Пенсия: что остаётся и уходит

Остаётся (клуб): золото, постройки и участки (`club`), шкафчик (кроме вещи, выбранной реликвией),
острова (`titles_by_loc`), `titles`/`played`/`best_round`, стиль, ставки, золотые, `lifetime_xp`.
Уходит (личное): навыки, перки, очки, внешность (наследник приходит со своей), надетое и сумка
последнего забега — продаются на «прощальном аукционе» за ½ цены (`Items.price / 2`) в банк;
вещь, которую итог забега уже положил в шкафчик, не продаётся.

## 4. Контракты для потока T (академия)

**Наследники.** `Career.register_heir_source(id: String, fn: Callable, prio := 0)`; повторная
регистрация того же `id` заменяет. `fn.call(ctx) -> Array[Dictionary]`, `ctx = {"gen", "seed",
"count", "retiring": <запись ушедшего>}`. `Career.heir_candidates()` опрашивает источники по
убыванию `prio`, берёт до 3 и добирает свободными агентами (`Career.free_agents`, по сиду
`Opponents.random`, тир E/D). Набор фиксируется в `career.heirs` до конца пенсии. Кандидат:

```gdscript
{"id": "j7", "name": "Миша Петров", "short": "ПЕТРОВ", "age": 17, "look": {...Looks},
 "levels": {"serve": 6, ...},          # уровни Skills.LIST (0..25) — станут навыками героя
 "stats": {"serve": 7, ...},           # 1..10 Opponents.STAT_KEYS, для карточки (необязательно)
 "traits": [], "origin": "academy",    # "free" у свободных агентов
 "perk": "", "note": "воспитанник академии · наставник Дима"}   # необязательные
```

Выбранный становится героем: `Skills.profile_from_levels(levels)` + `START_POINTS`, перк `perk`
(если есть) взят, внешность `look`, имя `name`, сезон 1, 19 лет, поколение +1. Сигнал
`GameEvents.career_retired({"record", "heir"})` — академия убирает выпускника из своих списков.

**Ушедший → NPC-тренер.** `SaveData.career["retired"]` — массив записей (новые в конце):

```gdscript
{"id": "p1", "gen": 1, "name": "Дима", "look": {...}, "seasons": 5, "runs": 20, "titles": 3,
 "best_rank": 7, "career_pts": 6120, "levels": {"serve": 21, ...}, "perks": ["sv_bomb"],
 "best_skill": "serve", "relic": {...} | {}, "early": false, "played_at": 57}
```

`best_skill` — специализация тренера (TZ 3.4); `look` — для `Looks.aged`. Профиль-призрак (L3)
добавит поле `ghost`, не меняя остальных.

**Карьера ученика (tycoon 3.7).** Функции, работающие со словарём карьеры, публичны:
`Career.new_career(name, gen, start_played)`, `Career.bank_into(c, t)`, `Career.xp_mult_of(c)`;
`academy.students[i].career` может хранить тот же словарь.

**События:** `GameEvents.season_over({"season", "pts", "rank", "gold", "retire"})`,
`GameEvents.career_retired({"record", "heir"})`.

## 5. Решения (принятые здесь, подтвердить)

1. ~~Первый герой без имени~~ — заменено разделом 6: у героя всегда есть имя. Имя наследника — от кандидата (случайное).
2. Финал сезона — на высшем открытом острове; ниже — без бонуса (как в TZ 3.2).
3. Прощальный сезон: ×1.2 на все призовые сезона (а не только на победы) — одна формула.
4. Свободный агент: уровни из статов (`стат − 2`, 0…3; касание — среднее форхенда, бэкхенда и
   сетки) + 3 стартовых очка — «тот же новичок, но со своей формой игры».
5. Золото за место в рейтинге сезона: 40 вне топ-100, 100…300 в топ-100 (не через доход забега).
6. Пенсия блокирует старт турнира, пока не пройдена церемония (крючок в `_start_tournament`).
7. Перезагрузка посреди церемонии: всё применяется на последнем шаге одним вызовом
   (`Career.retire`), до него ничего не меняется — церемония начинается заново.

## 6. Имя героя (поток N, решение владельца 10.10)

«Имя нужно, чтобы в кастомизации можно было выбирать и настраивать»; «у наследника будет рандомное
имя — потом можно за 100 монет поменять».

- **Данные:** `career.name` (всегда непустое), `career.renames` (сколько раз меняли). Старый сейв с
  пустым именем получает имя при загрузке (`Career.migrate`).
- **Имя по умолчанию** (первый запуск, старый сейв): `first_name` из Telegram (веб, `initDataUnsafe`),
  иначе случайное из генератора имён ростера (`OpponentGen.NAMES` через `Opponents.random`).
- **Допустимое:** кириллица, латиница, цифры, пробел, дефис; лишнее вырезается, пробелы схлопываются,
  не длиннее `Career.NAME_MAX` = 14 (влезает в табло, карточку, плашку клуба); мат из `ClubBuilds.BAD_WORDS`
  отклоняется; пустое нельзя. Длинное имя генератора («Властимил Кратохвил») становится одним именем.
- **Цена** — `Career.RENAME_COST` = 100 золота из банка, одна константа. **Первая смена самого первого
  героя (`gen == 1`, `renames == 0`) бесплатна** (поправить имя из Telegram). Дальше, и у любого наследника, —
  100. «Случайное» и «Из Telegram» подставляют имя в поле, платит только «СОХРАНИТЬ»; «Отмена» и «← Назад» —
  без списания. Нехватка золота: кнопки неактивны, подпись «нужно 100».
- **Где менять:** экран «Внешность» (строка «Имя: …» над превью, кнопка «Изменить 100» с монетой) и строка
  «Имя героя» в Раздевалке; оба ведут на экран `career_rename`: поле ввода, «Случайное» (кубик), «Из Telegram»
  (если есть), в вебе ещё «Ввести окном» (`window.prompt`, запасной путь, если экранная клавиатура не открылась).
  Во время матча кнопок нет (экраны меню).
- **Наследник:** имя случайное (кандидат), на выборе наследника ввода нет; менять потом за 100.
- **Где показано:** плашка игрока в клубе, Тренерская (строка сезона), итоги сезона, церемония пенсии,
  запись ушедшего (`retired[].name`, тренеры клуба), табло матча (`Career.hero_short()` — первое слово
  заглавными вместо «ВЫ»), таблица итогов матча. Выкрики диктора (`Calls`, «YOU») по-английски не тронуты.
- **Решения на подтверждение:** (а) бесплатная первая смена только у первого героя; (б) лимит 14;
  (в) табло показывает первое слово имени заглавными, длинное обрезается «…».
