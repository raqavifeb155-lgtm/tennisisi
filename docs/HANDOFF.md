Дата: 2026-10-08. Написал сборщик (интегратор) с Windows-компьютера. **Новый Claude на Mac:
прочитай этот файл целиком, потом `docs/handoff/claude-memory/*.md` (память прошлых сессий:

(строго эта версия: 4.7 переписывает файлы проекта), GDScript, сцена собирается из кода.

  https://tennis.150.241.228.228.sslip.io/, бот @TennisisiBot.

- **Сейчас на проде:** `main` @ `12ae6ab`, пакет `index.56afb21da1.pck` (v0.2a, 08.10).

**Цель — патч v0.2 «до онлайна»:**

## 5. Как работать (правила, выстраданные)

- **Потоки — отдельные чаты в своих ветках-копиях** (`git worktree add ../tennis-X -b
  <ветка> main`). Владение файлами и крючки — по плану v0.2 (раздел 2–3). Логика слушает
  `GameEvents` и не встраивается в `main.gd`. `main.gd`, `hud.gd`, `tournament_ui.gd` —
  файлы сборщика: потоки правят их только маленькими отдельными коммитами-крючками.
- **Проверка каждого слияния** (`$G` — Godot 4.4.1):
  ```bash
  $G --headless --path . -s tests/run_tests.gd
  $G --headless --path . -s tests/roguelike_test.gd
  $G --headless --path . -s tests/ui_test.gd
  $G --headless --path . -s tests/audio_test.gd
  $G --headless --path . --fixed-fps 60 -s tests/input_test.gd
  $G --headless --path . --fixed-fps 60 -s tests/anim_test.gd -- --body=0   # и 1, 2
  $G --path . -s tools/overlay_probe.gd      # сейчас 38 проверок, 4 провала (C-2)
  $G --headless --path . --fixed-fps 60 -- --autoplay --tournament --format=1 --bot-sd=0.07
  $G --path . -s tools/menu_shots.gd         # 720x1564 = iPhone 17 Pro Max
  $G --path . -s tools/menu_shots.gd -- --size=1480   # маленький Android
  ```
  Снимки — в user data Godot (путь печатается). На Mac рендер обычный (Metal/OpenGL),
  флаг `--rendering-driver opengl3` даёт тот же рендер, что веб.
- **Баланс ботом:** `--bot-sd=0.07` — точность «как палец на телефоне», `--xp=N` — опыт
  навыков. Замер отрисовки: `--profile --gfx=N`.
- **Выкладка** — только из закоммиченного `main`, только с «ок» владельца:
  ```bash
  git archive --format=tar HEAD | gzip | ssh fi 'rm -rf /opt/build/tennis-src && mkdir -p /opt/build/tennis-src/build && tar xzf - -C /opt/build/tennis-src && touch /opt/build/tennis-src/build/.gdignore && sed -i "s/\r$//" /opt/build/tennis-src/tools/*.sh && cd /opt/build/tennis-src && bash tools/build_web.sh && bash /opt/apps/tennis/update-build.sh /opt/build/tennis-src/build/web; cd /opt/apps/tennis && docker tag tennis-web:latest tennis-web:prev && docker compose -p tennis -f docker-compose.yml -f docker-compose.fi.yml up -d --build'
  ```
  Откат: `docker tag tennis-web:prev tennis-web:latest && docker compose -p tennis -f
  docker-compose.yml -f docker-compose.fi.yml up -d`.
- **Телеметрия с телефонов:** `ssh fi 'docker logs --since 24h tennis-web-1 | grep e=beat'`.
  Поля: `fps`, `low`, `worst`, `cpu` — время наших скриптов, `draws`, `px`, `gfx`.
- **Лимиты:** на Pro больше двух потоков параллельно окно не держит. Гонять 2 потока +
  сборщик, остальные — по очереди.
- **Python-скрипты правок:** писать с `newline=''`, иначе на Windows ломались переносы.
  На Mac не критично.

## 8. Решения владельца, которые нельзя забыть

- **Меню:** один фирменный цвет (тёмная база + золото), Balatro-карточки, 3D-корт за меню,
  шрифты Russo One + Golos Text. Выкрики в матче по-английски, остальное по-русски.
- **Клуб:**
  - ходибельный, одна кнопка у места, быстрый переход;
  - покупки ~70% флекс / 30% маленькая польза; в онлайне на силу не влияет;
  - модели — CC0-наборы (KayKit, Quaternius, Kenney) под общий мультяшный материал.
- **Ставки:**
  - только игровое золото, **никогда Stars и деньги**;
  - Тотализатор открывается после первого выигранного турнира.
- **Онлайн:** вызов другу → 1 на 1 → пара против ИИ → 2 на 2; без карьеры, равные статы.
- **Жесты:**
  - вверх прямо — плоский;
  - вверх и выкрут — топспин;
  - вниз — слайс;
  - короткий вниз — укороченный;
  - медленная дуга вверх — свеча.
- **Прод:** выкладывать частями по готовности, но только проверенное и с «ок» владельца.
- **Звуки:** только популярные с Pixabay, качать через сервер.

     `scripts/run/*` и ROGUELIKE_DESIGN 6.7; проверить ботом, сколько эпиков, легенд и

   - Надетое **видно на игроке**: у каждой вещи свой уникальный скин — ракетка (рама,
     обмотка, свечение по редкости), кроссовки, напульсник. Мифическая издалека
     узнаётся.
   - Рост силы от уровней и шмота должен ощущаться в матче.
3. **[D] Сложность начала игры — сделать сложнее и менее удобной первое время.**
   - Окно PERFECT уже и кольцо быстрее на низких уровнях.
   - Теннисист медленнее, удары менее точные.
   - До 5–10 уровня навыков не должно получаться держать розыгрыши по 40 ударов и часто
     подавать эйсы.
   - Править кривые в `scripts/skills.gd` (`stroke()`, `run_speed_mult()`), не ломая
     поздние уровни.
   - Цель для бота: новичок (`--bot-sd=0.07`) — средний розыгрыш ≤ 8 ударов, эйсов
     ≤ 1 за гейм своей подачи.
4. **[D] Эксплойт подачи на вылет:** подача по диагонали к боковой линии слишком часто не
   берётся. Нужно:
   - приёмщик ИИ заранее смещается к широкой подаче (читает позицию подающего и
     историю подач игрока);
   - больше дотягивание на приёме;
   - у новичка подача на вылет чаще уходит в аут.
   - Проверка ботом: доля эйсов при подаче на вылет до и после.
5. **[D] ИИ умнее — розыгрыши интереснее.** Ответ владельцу: да, можно, и дёшево по
   производительности (решение ИИ принимается раз за удар). План:
   - **выбор удара по ситуации:** где ты стоишь, насколько тебя растянули, качество
     твоего мяча. Короткий мяч → выход к сетке; ты глубоко за линией → укороченный; ты у
     сетки → свеча или обводящий; нейтрально → терпение и смена направления;
   - **стили соперников** (`scripts/opponents.gd`): атакующий, контрпанчер, сетевик,
     бомбардир — разные пропорции;
   - **«читает» игрока:** запоминает твои привычки за матч (куда подаёшь, что бьёшь с
     бэкхенда) и подстраивается;
   - **ошибки по давлению, а не «пока кто-то не ошибётся»:** ошибается чаще, когда
     растянут или под тяжёлым мячом.
   - Метрики бота: доля укороченных и выходов к сетке у ИИ, распределение длины
     розыгрышей, доля очков, выигранных «активно» (виннер или вынужденная), против
     невынужденных.
6. **[сборщик] FPS:** всё выше «Средней» в Telegram даёт нестабильный FPS. «Авто» на
   телефонах — максимум «Средняя». «Высокая» и «Максимум» — с пометкой «может тормозить
   в Telegram». Продолжить оптимизацию по `docs/PERFORMANCE.md`.
