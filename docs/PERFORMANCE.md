# Производительность: замеры и план

Дата: 2026-10-07. Главная платформа — Telegram на телефоне (WebAssembly + WebGL2, один
поток). Цель — стабильные 60 FPS на iPhone и ≥ 50 на среднем Android на «Низкой».

## 1. Что видно сейчас

**Телеметрия с прода** (до 07.10, 3 сессии): iPhone в Telegram — 41–43 FPS на «Высокой»,
масштаб 3D 0.78, память 80 МБ. Замер был в первые секунды после старта. С 07.10
телеметрия (`beat`, раз в 20 с) шлёт:
- `fps` — средний;
- `low` — худшие 5% кадров;
- `worst` — самый долгий кадр, мс;
- `cpu` — время процесса и физики, мс;
- `draws` — вызовы отрисовки;
- `tris` — треугольники в тысячах;
- `px` — пиксели 3D в тысячах;
- `ui`, `pause` — открыто ли меню или пауза.

Смотреть так: `ssh fi 'docker logs --since 24h tennis-web-1 | grep e=beat'`.

**Профиль на ПК** (рендер совместимости, как в вебе, 720×1564, матч в Нью-Йорке):

| Что включено | Вызовы отрисовки | Треугольники |
|---|---|---|
| Всё (Высокая) | ~450 | ~170k |
| Без теней | 274 | 95k |
| Без теней и без декораций | 153 | 22k |
| С тенями, без декораций | 151 | 22k |

**Выводы:**
- Тени удваивают нагрузку, и почти вся она — от **декораций у корта**: 64 отдельных
  объекта в радиусе ~8 м (скамейки, стул судьи, столбы, части забора). Дальние объекты
  уже без теней и собраны в MultiMesh.
- Солнце уже экономное: `SHADOW_ORTHOGONAL`, одна зона.
- Остаток ~150 вызовов без декораций — корт, мяч, сетка и **игроки**: каждый собран из
  десятков отдельных мешей частей тела с обводкой.
- Для мобильного WebGL в одном потоке 400+ вызовов отрисовки — главный подозреваемый.
  Подтвердить по телеметрии (`draws` против `fps` на реальных телефонах).

## 2. План (по выгоде)

1. **Слить ближние декорации** в один меш на материал при сборке сцены. Нужна утилита
   `MeshMerge`: статичные MeshInstance3D одного материала → один ArrayMesh. Ожидаемо
   −100…−150 вызовов (с тенью). Внешний вид не меняется.
2. **Мелкие детали без тени:** части меньше ~0.3 м (кисти, мелкие детали стула, фонари)
   не отбрасывают тень.
3. **Игроки:** обводку и тень оставить только крупным частям (торс, ноги, руки); мелкие
   части без обводки. Проверить `anim_test` и снимки.
4. **Стартовый пресет по устройству:** если телеметрия покажет < 55 FPS на iPhone в
   матче — начинать со «Средней» (масштаб 3D ниже), а «Авто» оставить.
5. **Проверка перед выкладкой:** `--profile` на ПК (вызовы ≤ 250 в матче на «Высокой») и
   телеметрия реальных телефонов после выкладки.

Сделано 07.10: дальние декорации (центр дальше 22 м или выше 25 м) без тени
(`Main._trim_shadows`) — экономия небольшая (−14 вызовов). Основное — в пунктах 1–3.

## 3. Бюджеты для новых вещей (клуб, эффекты вещей)

Повторяют CLUB_HUB_TZ 9:
- клуб ≤ 70 вызовов и ≤ 25k треугольников на «Низкой»;
- у каждого эффекта есть дешёвый вариант;
- частиц ≤ 64 на экране;
- эффекты не ярче мяча.

Клуб и матч никогда не живут одновременно.

## 4. ПК-версия (после v0.2)

Отдельная сборка Windows и Mac из того же проекта: рендер Forward+, многопоточность,
пресет «Ультра», управление мышью, клавиатурой и геймпадом. Сначала тест на itch.io,
потом Steam. Telegram-версия остаётся главной; бюджеты выше — для неё.
